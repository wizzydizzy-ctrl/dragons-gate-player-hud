# Hybrid HUD, persistent chat, and special sub-map acceptance

Use only the disposable `Dragons Gate HUD` profile. Do not send representational game messages solely to create test traffic: use already-observed output or synthetic local lines in the disposable profile.

Clock acceptance: after character entry, confirm the startup sequence ends with `time`. The header's Real Time must match the computer timezone and tick every second. Game Time must advance one minute per 30 real seconds, show `Daytime` from 6:00 AM through 5:59 PM and `Night` otherwise, and resynchronize after manually entering `time`. Resize through wide, medium, and compact modes and confirm both lines remain inside the header.

1. Build the unreleased package locally and install it only into the disposable profile. Record the profile's existing personal triggers, aliases, scripts, packages, map data, and settings before installation.
2. Confirm Identity and Character/Combat are left, Vitals/Location are lower-left, and Equipment/Wealth/Inventory are right. Enter a character and confirm exactly one sequential `inventory`, `stat`, `info` refresh.
3. Compare inventory, weapon/shield readiness, attributes, physical details, armor, OR/DR, movement, damage bonus, stance, and novice protection with command output. Run each command manually and confirm its HUD section refreshes.
4. Confirm available compass directions are bright and clickable; unavailable directions are dim and inert. In a safe test room, verify `GO PORTAL`, `GO DOOR`, `GO GATE`, and `GO ARCH` send their exact commands.
5. Confirm the chatbox is always visible directly above the center console, precisely matches the console's left edge and width, and does not change normal game output.
6. Feed the approved ROOM, OWN, WHISPER, ESP, DRAGON, CONTACT, and STAFF examples through the real line-capture path. Verify each is retained under its exact category and appears through the appropriate `ALL`, `ROOM`, `PRIVATE`, or exact-category filter.
7. Feed misleading NPC/system narration containing words such as `says`, `asks`, `exclaims`, or `whispers`. Confirm it is not captured and remains unmodified in the main console.
8. Feed the same ESP entry twice adjacently within three seconds. Confirm it appears once. Feed a later, non-adjacent, or different-speaker equivalent and confirm it remains.
9. Create one temporary personal trigger that calls `DGHUD.chat.capture("QUEST", line)`. Trigger it with a synthetic local line, confirm a `QUEST` filter becomes available, then retain the trigger for the reload checks below.
10. Run `dghud chatstatus`. Confirm it reports the active filter, visible count, sanitized active-character storage key, and `last storage error=none` unless you intentionally created a local storage failure.
11. Inspect `<Mudlet home>/DGHUDData/chat/<safe-character-name>/YYYY-MM-DD.jsonl`. Confirm one valid JSON object per captured entry, append-only behavior, no path traversal components, and that private entries are treated as locally sensitive data.
12. Run `dghud reload` repeatedly. Confirm exactly one owned chat capture trigger remains, old chat entries reload, `DGHUD.chat.capture("QUEST", line)` still works, and the temporary personal trigger is neither modified nor removed.
13. Disconnect and reconnect, then restart Mudlet in the disposable profile. Confirm the latest entries reload while older JSONL files remain on disk and unrelated personal runtime remains unchanged.
14. Resize through approximately `2560x1400`, `1920x1080`, `1200x800`, `1000x650`, compact width, full-screen, and restored-window sizes. Confirm the chatbox remains top-center, readable, non-overlapping, and above a usable console. Check a long entry narrows/widens with the center display without clipping, losing its selected filter, or jumping the reading position.
15. Run `lua display({version=DGHUD.settings.version,healthy=DGHUD.healthCheck()})` and confirm the installed version and `healthy=true`. Recompare the pre-install inventory of unrelated triggers, aliases, scripts, packages, map data, and settings.
16. Confirm the native mapper is directly above the compass at wide, medium, restored, and short-window sizes. In compact mode, confirm hiding it leaves no overlap or black gap. Its usable height should not fall below the configured 90-pixel default when visible, while wide mode retains its 140-pixel responsive floor. Temporarily raise `DGHUD.user_settings.mapper.minimum_height`, reload, and confirm feasible layouts materially grow the mapper or hide it cleanly when the requested floor cannot fit. Repeat at full-screen and restored-window sizes.
17. In safe training rooms, run `lua display({id=gmcp.Room.Info.num,area=gmcp.Room.Info.area})` before each move. Walk through standard exits and confirm each canonical GMCP number creates one HUD-owned native room with advertised stubs and only observed links. Revisit a room, run `look`, and cross a known link in both directions; the same room ID, area, partition, and coordinates must remain, with no duplicate or overlap.
18. From a mapped origin, use a known safe non-direction travel command such as `go door`, `go gate`, or `go arch` to a previously unmapped destination, and confirm the different destination GMCP room arrives within three seconds. That newly discovered destination must start its own destination-rooted sub-map; subsequent directional rooms in the same game area must remain in it. Then enter an already mapped canonical destination through a confirmed non-direction command and confirm only the observed one-way edge is added: the existing room must retain its saved partition and coordinates without duplication or movement.
19. Before observing a return command, try to route back to the special origin and confirm no reverse special edge was invented. Then use the real safe return command and confirm only that exact observed one-way edge appears. Let another eligible candidate sit for more than three seconds before changing rooms and confirm it creates no edge. Run representative excluded controls—`look`, `inventory`, `dghud mapstatus`, and `walkto <room number>`—then change rooms normally and confirm none is recorded as a special exit.
20. In each normal area and special sub-map, click `−`, center, and `+`. Confirm `−` makes the map visually smaller, center selects the current canonical room, and `+` makes the map visually larger. Set visibly different zoom levels in two areas, move between them, run `dghud reload`, and restart the disposable profile; each area's own zoom must return without affecting the other area.
21. Choose a known owned destination whose native Mudlet route mixes standard directions with already-confirmed special exits. Run `walkto <room number>` and repeat by clicking that destination. Confirm exactly one command is sent for each expected `gmcp.Room.Info.num`, special command text is preserved exactly, and no next command is sent early. Cause nonzero roundtime after an intermediate arrival and confirm walking resumes only after `gmcp.Char.Vitals.roundtime` reaches zero. Separately verify `walkstop`, `mapcenter`, WrongDir, timeout, unexpected-room, manual-movement, and disconnect cancellation in a safe noncombat location with an empty command line.
22. Run `dghud mapstatus`. Confirm it reports enabled state, current room, managed count, active destination, last status, and last actual error. Verify ordinary `walkstop`, manual movement, route replacement, and shutdown do not replace an earlier real error. Confirm diagnostics do not print room names, routes, the personal test room, or unrelated map data.
23. Run `dghud reload`, then restart the disposable profile. Confirm canonical HUD rooms, sub-map partitions, observed special exits, coordinates, and area zoom remain usable; no mapper runtime is duplicated; and the pre-existing personal room is unchanged. Shut down/uninstall the HUD package and confirm its runtime handlers, aliases, timers, click hook, and panels are removed while native map records and unrelated runtime remain.
24. Before cleanup testing, confirm the host provides `/dev/urandom`: cleanup preview requires this secure entropy source and fails closed without changing the map when it is unavailable. Standard Windows environments are unsupported for cleanup preview until a supported secure entropy source exists. Then export or byte-record a personal test room and area, including room/area IDs, names, coordinates, ordinary exits, special exits, labels, and every metadata value. Also record unrelated personal triggers, aliases, scripts, settings, packages, and chat logs. Create a deliberately isolated HUD-owned test submap with no inbound exit from personal or unowned rooms.
25. Move out of the test submap to a known safe room, ensure no movement or transition is pending, and run `walkstop`. Preview `dghud map clear submap <root-room-id>`. Verify the output identifies the exact owned area and complete sorted room-ID set without changing any recorded map content.
26. Run `dghud map cancel`, then try the old token. Confirm both cancellation and rejected confirmation cause zero map mutation. Create another preview, wait more than 30 seconds, and confirm its token; verify expiry causes zero mutation and the consumed token cannot be reused.
27. Create a fresh preview, then safely change its membership or ownership evidence before confirmation. Confirm the stale preview is rejected with zero mutation. Restore the isolated fixture explicitly; do not use a force path or broaden ownership to make the preview pass.
28. In the isolated HUD-owned submap, arrange a controlled room-deletion failure after at least one lower-numbered room can be deleted. Confirm cleanup stops immediately and reports exact deleted, failed, and untouched IDs. Confirm the surviving rooms and owned area remain, the area is not deleted, the consumed token cannot be retried, and the map refreshes to the actual surviving state.
29. Restore the isolated fixture, preview it again, inspect every ID, and confirm within 30 seconds. Verify only the selected HUD-owned rooms and then the empty still-owned area are deleted. Revisit each deleted canonical room and confirm normal GMCP mapping recreates it cleanly.
30. Byte-compare the personal room, area, names, coordinates, ordinary exits, special exits, labels, and metadata against the record from step 24 after cancel, expiry, stale-preview rejection, partial failure, successful cleanup, and remapping. Recompare unrelated runtime, settings, packages, and chat logs. Every personal and unrelated byte/value must remain unchanged.
31. Only after independent review and release authorization: complete the updater/published-artifact acceptance separately. Install the published release in a safe live moment, run `dghud update`, verify checksum/health, then repeat the chat, mapping, sub-map persistence, custom-trigger, mixed walking, all three map controls, diagnostics, full-screen, and restored-window checks. Confirm the update replaces only the `DragonsGateHUD` package code and preserves user settings, chat logs, canonical rooms, partitions, observed exits, per-area zoom, unrelated runtime, and personal map content. Do not treat this source-worktree checklist as permission to publish or update a live profile.
32. Resize the disposable profile to approximately `1000x900` and `1024x768`. Confirm the Skills card shows five rows, remains vertically scrollable through every retained skill, and keeps its name, `LVL`, and `USES` columns visible and aligned without text beneath the scrollbar.
33. On a `3840x2160` or comparable high-DPI display with operating-system scaling enabled, repeat the Skills check. Confirm all three columns remain visible and aligned and the console gutters remain subtle, equal, and capped rather than growing proportionally with the display width.

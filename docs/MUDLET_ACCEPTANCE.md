# DGHUD v0.3.95 manual acceptance checklist

This is a checklist for a disposable test profile, not a claim that these live checks were performed. Never use it as permission to change a live profile or publish a release.

Skill-filter toggle acceptance: in both editions, open **OPTIONS → Skill Settings** with fresh or legacy settings lacking `display.skill_filter` and confirm **SKILL FILTERS: ON** is first in the scroll area. Toggle OFF, then Cancel or dismiss the panel; reopening must show the active ON choice. Toggle OFF and Save; reopen and confirm OFF. Reset must show ON only in the draft until Save. Simulate a failed Save and confirm the draft/error stays visible while the active choice stays unchanged. Resize through narrow and short windows; the toggle, explanation, tabs, and Save/Cancel must remain readable, non-overlapping, and reachable by scrolling.

With filters saved OFF, verify `skill Rath`, a mixed-case name with repeated spaces, and each argument form `skill all`, `skill weapons`, `skill combat`, `skill utility`, and `skill train` reaches a local send recorder unchanged exactly once. Repeat while a refresh is busy and while local filtering/display support is unavailable; no local search, pending filter, or artificial rejection may occur. Start a pending filter with ON, save OFF, and confirm its timer/filter cannot affect later output. Bare `skill` must still capture the complete sidebar and follow MAIN SKILLS formatting in either filter mode. Changing MAIN SKILLS, text size, wrap, or input alignment must preserve saved OFF. Verify it survives reload, update, and cold start, including reusable-view adoption; a preserved view missing the filter widget or callback must be rejected. Use local fixtures/recorders for these checks, not representational commands sent to a live game.

Color acceptance: open **OPTIONS → COLOR SETTINGS → TEXT STYLES**. Change Exit directions to a blue foreground with a dark background, bold and underline; Save and verify only directions on new output change. Change one race, disable one class style, and check repeated names on the same line. Verify all style entries are reachable by scrolling at compact and normal window sizes, a draft survives resizing, Cancel does not save, and Reset Default requires Save. Reload/update and cold-load the saved data to verify the choices persist. Revert test choices afterward.

Feed synthetic local mixed lists into the real trigger path: a store/pawnshop/tavern with a fountain; a dark hole plus a torch split before “here.”; SHOP instructions followed by “An exit is here.”; an arch/door spanning lines; a dirt path alongside a lamp post. Confirm travel phrases use their travel style, other listed objects use the separate presence style, and `is here` / `are here` use their own style, including across prior lines. Disable OTHER OBJECTS / HERE and confirm non-travel objects stay unchanged. Quoted chat and unrelated narrative mentions must remain untouched. Inject a replaced old console line and verify it is skipped. Do not publish private logs as fixtures.

Use only a new disposable Mudlet profile, not an existing game profile. Do not send representational game messages solely to create test traffic: use already-observed output or synthetic local lines in the disposable profile.

Clock acceptance: after character entry, confirm the startup sequence ends with `time`. The header's Real Time must match the computer timezone and tick every second. Game Time must advance one minute per 30 real seconds, show `Daytime` from 6:00 AM through 5:59 PM and `Night` otherwise, and resynchronize after manually entering `time`. Resize through wide, medium, and compact modes and confirm both lines remain inside the header.

Input alignment acceptance: turn **OPTIONS → ALIGN INPUT** on with an unsent draft. Confirm only the native input's left edge follows the main display, while native Search and status controls remain visible on the right. Resize and verify the draft survives and the input ends before those controls. Turn alignment off and confirm the original stylesheet and compact-input preference return. Repeat from a saved 0.3.58 aligned state (compact input plus both margins), then verify upgrade/reload keeps the saved choice but uses left-only alignment without accumulating margins.

Mudlet starter UI acceptance: in a disposable Mudlet 5 profile that has the `mudlet-base-ui` package, install DGHUD while the starter dock has no saved show/hide choice. Confirm only the extra dock hides, leaving main game text, input, native toolbar, and DGHUD mapper usable. Choose **OPTIONS → MUDLET UI: OFF** to show it and **ON** to hide it; resize in MultiView and verify the Options button remains reachable. Show it again, reload/update DGHUD, and restart the profile; the explicit choice must survive. Remove the starter package in the disposable profile and confirm clicking the option reports unavailability without sending a command to the game.

1. Build the v0.3.95 package locally and install it only into the disposable profile. Record the profile's existing personal triggers, aliases, scripts, packages, map data, and settings before installation.
2. Confirm Identity and optional Equipment are left, Combat plus Inventory/Runes/Skills are right, Location/mapper/compass are lower-left, and Vitals span the center immediately above the input line. Enter a character and confirm exactly one sequential startup refresh.
3. Compare inventory, weapon/shield readiness, attributes, physical details, armor, OR/DR, movement, damage bonus, stance, and novice protection with command output. Run each command manually and confirm its HUD section refreshes.
4. Confirm available compass directions are bright and clickable; unavailable directions are dim and inert. In a safe test room, verify `GO PORTAL`, `GO DOOR`, `GO GATE`, and `GO ARCH` send their exact commands.
5. With SHOW CHATBOX on, confirm the chatbox sits directly above the center console and matches its left edge and width. Turn it off and confirm the console expands while capture and saved history continue; turn it on again and confirm history returns. Normal game output must remain unchanged.
6. Feed the approved ROOM, OWN, WHISPER, ESP, DRAGON, SECIAN, CONTACT, and STAFF examples through the real line-capture path. Include direct-target forms such as `Eilan asks Atrax, "..."` and `You ask Atrax, "..."`. Verify each is retained under its exact category, that ROOM includes both ROOM and OWN entries, and that every entry appears through the appropriate `ALL`, `ROOM`, `PRIVATE`, or exact-category filter.
7. Feed misleading NPC/system narration containing words such as `says`, `asks`, `exclaims`, or `whispers`. Confirm it is not captured and remains unmodified in the main console.
8. Feed the same ESP entry twice adjacently within three seconds. Confirm it appears once. Feed a later, non-adjacent, or different-speaker equivalent and confirm it remains.
9. Create one temporary personal trigger that calls `DGHUD.chat.capture("QUEST", line)`. Trigger it with a synthetic local line, confirm a `QUEST` filter becomes available, then retain the trigger for the reload checks below.
10. Run `dghud chatstatus`. Confirm it reports the active filter, visible count, `profile` storage key, and `last storage error=none` unless you intentionally created a local storage failure.
11. Inspect `<Mudlet home>/DGHUDData/chat/profile/YYYY-MM-DD.jsonl`. Confirm one valid JSON object per captured entry, append-only behavior, no path traversal components, and that private entries are treated as locally sensitive data.
12. Change characters in the same Mudlet profile and confirm the existing chat history and selected filter remain unchanged while new entries append to the same profile history.
13. Run `dghud reload` and `dghud update`. Confirm the visible chat is not blanked or repainted, its reading position remains stable, exactly one owned chat capture trigger remains, and the temporary personal trigger is neither modified nor removed.
14. Disconnect and reconnect, then restart Mudlet in the disposable profile. Confirm the newest combined profile and legacy character entries reload without exact duplicates while older JSONL files remain on disk and unrelated personal runtime remains unchanged.
15. Resize through approximately `2560x1400`, `1920x1080`, `1200x800`, `1000x650`, compact width, full-screen, and restored-window sizes. Confirm the chatbox remains top-center, readable, non-overlapping, and above a usable console. Check a long entry narrows/widens with the center display without clipping, losing its selected filter, or jumping the reading position.
16. Run `lua display({version=DGHUD.settings.version,healthy=DGHUD.healthCheck()})` and confirm the installed version and `healthy=true`. Recompare the pre-install inventory of unrelated triggers, aliases, scripts, packages, map data, and settings.
17. Confirm the native mapper is directly above the compass at wide, medium, restored, and short-window sizes. In compact mode, confirm hiding it leaves no overlap or black gap. Its usable height should not fall below the configured 90-pixel default when visible, while wide mode retains its 140-pixel responsive floor. Temporarily raise `DGHUD.user_settings.mapper.minimum_height`, reload, and confirm feasible layouts materially grow the mapper or hide it cleanly when the requested floor cannot fit. Repeat at full-screen and restored-window sizes.
18. In safe training rooms, run `lua display({id=gmcp.Room.Info.num,area=gmcp.Room.Info.area})` before each move. Walk through standard exits and confirm each canonical GMCP number creates one HUD-owned native room with advertised stubs and only observed links. Revisit a room, run `look`, and cross a known link in both directions; the same room ID, area, partition, and coordinates must remain, with no duplicate or overlap.
19. Confirm every special-travel submap toggle defaults to OFF. With the toggle OFF, walk in one direction to an origin whose only ordinary return exit is the opposite direction, use a known safe non-direction travel command such as `go door`, `go gate`, or `go arch`, and confirm the new destination stays on the current map exactly one free space forward from the origin. Occupy that preferred coordinate and confirm the next deterministic adjacent space is used without moving an existing room. Enable the travel type and confirm another previously unmapped destination starts its own destination-rooted sub-map; subsequent directional rooms in the same game area must remain in it. Then enter an already mapped canonical destination through a confirmed non-direction command and confirm only the observed one-way edge is added: the existing room must retain its saved partition and coordinates without duplication or movement.
20. Before observing a return command, try to route back to the special origin and confirm no reverse special edge was invented. Then use the real safe return command and confirm only that exact observed one-way edge appears. Let another eligible candidate sit beyond the configured special-travel timeout (12 seconds by default) before changing rooms and confirm it creates no edge. Run representative excluded controls—`look`, `inventory`, `dghud mapstatus`, and `walkto <room number>`—then change rooms normally and confirm none is recorded as a special exit.
21. In each normal area and special sub-map, click `−`, center, and `+`. Confirm `−` makes the map visually smaller, center selects the current canonical room, and `+` makes the map visually larger. Set visibly different zoom levels in two areas, move between them, run `dghud reload`, and restart the disposable profile; each area's own zoom must return without affecting the other area.
22. Choose a known owned destination whose native Mudlet route mixes standard directions with already-confirmed special exits. Run `walkto <room number>` and repeat by clicking that destination. Confirm exactly one command is sent for each expected `gmcp.Room.Info.num`, special command text is preserved exactly, and no next command is sent early. Cause nonzero roundtime after an intermediate arrival and confirm walking resumes only after the tracked countdown reaches zero, including local expiry without a new zero GMCP packet. An unchanged stale packet must not restart it. Separately verify `walkstop`, `mapcenter`, WrongDir, timeout, unexpected-room, manual-movement, and disconnect cancellation in a safe noncombat location with an empty command line.
23. Run `dghud mapstatus`. Confirm it reports enabled state, current room, managed count, active destination, last status, and last actual error. Verify ordinary `walkstop`, manual movement, route replacement, and shutdown do not replace an earlier real error. Confirm diagnostics do not print room names, routes, the personal test room, or unrelated map data.
24. Run `dghud reload`, then restart the disposable profile. Confirm canonical HUD rooms, sub-map partitions, observed special exits, coordinates, and area zoom remain usable; no mapper runtime is duplicated; and the pre-existing personal room is unchanged. Shut down/uninstall the HUD package and confirm its runtime handlers, aliases, timers, click hook, and panels are removed while native map records and unrelated runtime remain.
25. Before cleanup testing, record whether the host provides `/dev/urandom`; hosts without it use DGHUD's bounded local confirmation-token fallback. Then export or byte-record a personal test room and area, including room/area IDs, names, coordinates, ordinary exits, special exits, labels, and every metadata value. Also record unrelated personal triggers, aliases, scripts, settings, packages, and chat logs. Create a deliberately isolated HUD-owned test submap with no inbound exit from personal or unowned rooms.
26. Move out of the test submap to a known safe room, ensure no movement or transition is pending, and run `walkstop`. Preview `dghud map clear submap <root-room-id>`. Verify the output identifies the exact owned area and complete sorted room-ID set without changing any recorded map content.
27. Run `dghud map cancel`, then try the old token. Confirm both cancellation and rejected confirmation cause zero map mutation. Create another preview, wait more than 30 seconds, and confirm its token; verify expiry causes zero mutation and the consumed token cannot be reused.
28. Create a fresh preview, then safely change its membership or ownership evidence before confirmation. Confirm the stale preview is rejected with zero mutation. Restore the isolated fixture explicitly; do not use a force path or broaden ownership to make the preview pass.
29. In the isolated HUD-owned submap, arrange a controlled room-deletion failure after at least one lower-numbered room can be deleted. Confirm cleanup stops immediately and reports exact deleted, failed, and untouched IDs. Confirm the surviving rooms and owned area remain, the area is not deleted, the consumed token cannot be retried, and the map refreshes to the actual surviving state.
30. Restore the isolated fixture, preview it again, inspect every ID, and confirm within 30 seconds. Verify only the selected HUD-owned rooms and then the empty still-owned area are deleted. Revisit each deleted canonical room and confirm normal GMCP mapping recreates it cleanly.

Byte-compare the personal room, area, names, coordinates, ordinary exits, special exits, labels, and metadata against the record from step 25 after cancel, expiry, stale-preview rejection, partial failure, successful cleanup, and remapping. Recompare unrelated runtime, settings, packages, and chat logs. Every personal and unrelated byte/value must remain unchanged.

Confirm the update replaces only the `DragonsGateHUD` package code and preserves user settings, chat logs, canonical rooms, partitions, observed exits, per-area zoom, unrelated runtime, and personal map content.
